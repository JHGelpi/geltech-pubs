# Launch checklist (Wes, by hand)

Claude doesn't do these: they touch DNS, Cloudflare settings or secrets. Work top to bottom.

- [ ] **1. DNS snapshot (G-1).** Cloudflare dashboard → geltech.dev → DNS → Records → Export. Keep the file outside this repo.
- [ ] **2. API token and secrets (FR-23).** My Profile → API Tokens → Create Custom Token (not the "Edit Cloudflare Workers" template, which grants far more). Permissions: **Account → Workers Scripts → Edit**, **Account → Account Settings → Read**, **Zone → Zone → Read**. Account Resources: your account only. Zone Resources: specific zone `geltech.dev`. No DNS permission is needed: Cloudflare creates the apex record when the Custom Domain is attached. Add the token to GitHub → Settings → Secrets and variables → Actions as `CLOUDFLARE_API_TOKEN`, and the **Account ID** (not the Zone ID; both are on the zone overview page) as `CLOUDFLARE_ACCOUNT_ID`. A deploy error "No access to the specified resource" means the token or account ID is wrong.
- [ ] **3. Fill in identity.** In `src/site.config.ts` set `tagline`, `bio`, `links.linkedin`, `links.x` (or delete a link you don't want). Then run `npm run og` and commit `public/og-default.png`. Replace the Dishkept summary in `src/content/projects/dishkept.md`.
- [ ] **4. Merge the deploy PR.** First delete any existing A, AAAA or CNAME record named `geltech.dev` (the apex); otherwise the deploy fails with "already has externally managed DNS records" (code 100117). Leave MX, TXT and every other name alone. The first CI deploy attaches `geltech.dev` as a Custom Domain on the Worker. Then check DNS: only the apex record changed; `dishkept` and every other record are untouched (G-2). Compare against the snapshot from step 1.
- [ ] **5. `www` redirect and HTTPS.** Make sure a **proxied** `www` DNS record exists (keep an existing one; if none, add `AAAA www 100::`). Then Rules → Create rule → Redirect Rule: hostname equals `www.geltech.dev` → dynamic redirect to `concat("https://geltech.dev", http.request.uri.path)`, status 301, preserve query string. Also turn on SSL/TLS → Edge Certificates → **Always Use HTTPS**. Check: `https://www.geltech.dev/about/` and `http://geltech.dev/about/` both 301 to `https://geltech.dev/about/`.
- [ ] **6. HSTS (G-3).** SSL/TLS → Edge Certificates → HSTS: if enabled, **Include subdomains must be off**.
- [ ] **7. Dishkept smoke test (G-5).** Open `https://dishkept.geltech.dev` and use it as normal.
- [ ] **8. Retire the old CV site.** Turn off GitHub Pages on `JHGelpi/cv`, or replace its `index.html` with a link to `https://geltech.dev/about/`.
- [ ] **9. First real post (§8).** After it's live: paste its URL into LinkedIn Post Inspector and check the X card. Title, description and image should be right.
